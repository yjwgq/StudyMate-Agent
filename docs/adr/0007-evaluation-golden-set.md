# ADR-7：自建检索层 golden set，先建立噪声地板

> 状态：**已实现**（M3 建立评测基建与 50 条 golden；M6 发现两个评测缺陷；M7 扩集重标）
> 实现落点：`evals/{metrics,gen_golden,build_golden_v2,run_eval,compare_pipelines,noise_floor}.py`、`evals/golden_v{1,2}.jsonl`、`evals/reports/`
> **RAGAS 未引入**（范围裁剪，见下）

## 背景

"效果变好"必须可量化、可归因：是**召回**变好了还是**排序**变好了？答案层指标（RAGAS 那一类）只能告诉你"答案好不好"，回答不了这个归因问题。而 v1 完全没有评测脚本——所以对照物本身就是必须自己造的交付物。

## 决策

自建**检索层指标**（Recall@k / MRR / nDCG@10）+ **固定 golden set** + **版本对比表**驱动优化；先做**噪声地板**再定门禁阈值。

## 替代方案

| 方案 | 放弃理由 |
|------|---------|
| 直接用 RAGAS（答案层） | ① LLM judge 有随机性，未测噪声前设门禁会频繁假红灯；② 无法区分"检索没召回"与"生成没用上"；③ **已随范围裁剪移出 MVP**（见"与设计文档的差异"） |
| 只用人工抽查 | 不可复现、不可比较、无法进 CI |
| 门户现成的榜单/数据集 | 与自有语料分布不符，无法反映真实退化 |

## 与设计文档的差异（按实际实现修正）

| 设计文档写的 | 实际做法 | 原因 |
|-------------|---------|------|
| RAGAS 四项（Faithfulness / Answer Relevancy / Context Precision / Recall） | **未引入**：只做检索层确定性指标 | 范围裁剪。答案层指标依赖 LLM judge（成本 + 随机性 + 需 judge 独立性设计），M7 的"0.5–1 周"预算装不下 |
| golden 50 → 320（四组各 60–120） | **68 条**：v1 的 50 条 + M7 的 18 条真实语料人工题 | 范围裁剪；且 M6 的实测表明"加题量"不如"加难度与修标注"有效（见下） |
| 噪声地板 = 2σ 门禁 | 噪声地板**实测 σ=0**（检索层是确定性计算） | 结论比预期更强：确定性指标可做**精确阈值门禁**，不需要 2σ 松弛；答案层指标的噪声地板仍是空缺（未引入答案层指标） |

## 实测中发现的两个评测缺陷（**本 ADR 最有价值的部分**）

### 1. 合成语料导致指标饱和（M6）

M3 的 10 篇合成文档彼此主题独立，结果：**单路向量与混合检索的 Recall@10 都是 1.0**，任何改进都无法体现。这不是"系统够好"，而是**评测集没有区分度**。
→ M7 引入**真实技术文档**（为人撰写、结构复杂、术语密集）后，指标重新有了区分度：MRR 从 1.0000 降到 0.9240（单路基线），改进空间显现。

### 2. 跨文档问的 rel 分级是**任意约定**（M6，方法论级发现）

v1 对"A 和 B 分别是什么"这类问句采用"查询里第一个术语所在文档记 rel=2、第二个记 rel=1"。但该查询对 A、B **同等权重**——精排按语义相关性排序时不可能也不应该学到这个人为约定。
实测后果：精排把 q046 **修好了**（nDCG 0.8918 → 1.0），却让 q047/q050 "变差"（1.0 → 0.8918），净效应看起来是"精排有害"。
→ M7 把跨文档问改为**对称分级 {2,2}**（`evals/build_golden_v2.py`），并把这段分析写进 `M6_验收手册.md`。
**面试价值**：能把"精排反而降分"定位到**标注口径**而非实现缺陷，比调参调出 0.1 个点更能体现方法论文素养。

## 代价与局限

1. **答案层指标缺失**：Faithfulness / Answer Relevancy 无实测数字；groundedness 校验器（`agent/guardrails/groundedness.py`）是启发式（引用标记覆盖率），不是 NLI 判分，两者不能互相冒充。
2. **语料是仓库文档快照**：golden_v2 的真实语料来自本项目文档，锚点自检会在文档改动后失败（设计如此：防标注漂移），但也意味着语料会随仓库演进而"过期"。
3. **召回指标仍饱和**：68 条里三条主管线 Recall@10 均为 1.0——要测召回能力需要设计"应召回但难召回"的负例（未做）。
4. **精排增益接近噪声量级**：M7 实测精排 +0.0098 MRR / −0.0013 nDCG（68 条样本），方向上互相矛盾，**不宜过度解读**。

## 影响

- 评测基建让 M6 的降级矩阵可被量化（向量路故障时 Recall@10 从 0 → 0.9926），这比"我觉得降级有用"有力得多。
- 对比与归因脚本（`evals/compare_pipelines.py`）一条命令跑五条管线，是 M7 验收 H1/H2 的直接产出。
- 评测方法论沉淀为 `docs/eval_report.md`（对外交付物之一）。
